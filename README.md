# SNAP ARENA

링크 하나로 친구와 붙는 브라우저용 3D 아레나 FPS. 해 질 녘 화물 창고를 배경으로 한 사실적인 톤 (이전 장난감풍 버전은 git 태그 `toy-v1`). 1 대 1과 2 대 2, 먼저 5라운드를 이기면 승리.
가입·설치 없이 PC Chrome / Edge에서 바로 플레이한다.

## 로컬 실행

Node.js 18 이상이 필요하다.

```bash
npm install
npm run build     # 클라이언트(dist)와 서버(dist-server)를 빌드
npm start         # http://localhost:3000
```

개발 중에는 `npm run dev` (서버 3000번 + Vite 5173번, 소켓은 자동 프록시). 포트는 `PORT` 환경 변수로 바꾼다.

## 친구 초대

1. 닉네임을 넣고 1 대 1 또는 2 대 2를 골라 **비공개 방 만들기**.
2. 로비의 **초대 링크 복사**를 눌러 친구에게 보낸다. 5자리 방 코드를 불러 줘도 된다.
3. 친구는 링크를 열고 닉네임만 넣으면 바로 입장한다.
4. 정원이 차고 모두 **준비**를 누르면 방장이 **경기 시작**.

같은 와이파이라면 `http://<내 PC의 내부 IP>:3000` 으로도 접속할 수 있다.
서로 다른 인터넷에서 하려면 아래처럼 서버를 공개 주소에 올려야 한다.

## 조작

| 키 | 동작 |
| --- | --- |
| WASD / Space / Shift | 이동 / 점프 / 질주 |
| 좌클릭 / 우클릭 | 발사·근접 공격 / 총기 조준 |
| R / 1 2 3 / F | 재장전 / 장비 교체 / 장비 살펴보기 |
| B 또는 ESC | 마우스 잠금 해제 (장비 변경, 감도·음량 설정). 화면을 클릭하면 복귀 |

느린 기기에서는 주소 뒤에 `?fx=low` 를 붙이면 그림자·환경 반사를 끄고 가벼운 재질과 낮은 해상도를 쓴다 (초대 링크라면 `&fx=low`).

## 배포

Node 프로세스 하나가 게임 서버(WebSocket)와 프론트 빌드를 함께 제공하므로, **Node와 WebSocket을 지원하는 호스팅**이면 된다
(예: Render, Railway, Fly.io 같은 컨테이너·웹 서비스형 호스팅, 또는 직접 운영하는 서버). 정적 호스팅 전용 서비스에는 올릴 수 없다.

- 빌드 명령: `npm ci --include=dev && npm run build`
- 실행 명령: `npm start`
- 포트: 호스팅이 주는 `PORT` 환경 변수를 그대로 사용한다. 상태 확인 주소는 `/healthz`.
- Docker를 쓰는 곳이라면 저장소의 `Dockerfile` 로 바로 빌드된다: `docker build -t snap-arena . && docker run -p 3000:3000 snap-arena`
- 방은 서버 메모리에만 있다. **인스턴스는 1개로** 두고(여러 대로 늘리면 방이 갈라진다), 서버가 재시작되면 진행 중인 방은 사라진다.
- 프록시 뒤에 둘 때는 WebSocket 업그레이드를 통과시켜야 한다. 막히면 Socket.IO가 롱폴링으로 내려가 지연이 커진다.

## 구조

```
shared/config.ts   경기 규칙·이동·장비 수치 (조정은 여기서)
shared/map.ts      맵 블록과 스폰
shared/sim.ts      서버와 클라이언트가 함께 쓰는 이동·충돌·무기 시뮬레이션
server/index.ts    방, 로비, 라운드, 판정 (서버 권위)
client/game.ts     입력, 예측·보정, 상대 보간, 연출, HUD
client/viewmodel.ts 1인칭 손·장비 애니메이션
client/models.ts   손, 칼, 총, 캐릭터 메시
client/audio.ts    합성 효과음
```

- 서버가 60Hz로 이동·충돌·발사 간격·탄약·재장전·피격·라운드를 판정하고 30Hz로 상태를 보낸다.
- 클라이언트는 입력과 시점만 보낸다. 내 움직임은 같은 시뮬레이션으로 먼저 예측하고 서버 값으로 보정, 상대는 100ms 뒤를 보간해 그린다.
- 사격 판정은 쏜 사람이 보던 시점(최대 400ms)으로 상대 위치를 되감아 계산한다.
- 연결이 끊기면 30초 동안 자리를 지킨다. 그 안에 같은 탭에서 링크를 다시 열면 원래 슬롯으로 돌아온다. 넘기면 기권.

## 수치 조정

`shared/config.ts` 한 파일에 모여 있다: 라운드 수·시간, 이동 속도, 총기별 탄창·연사 간격·피해·거리 감소·재장전·산포·반동 패턴, 칼 사거리·간격·타격 시점.
바꾼 뒤 `npm run build` 로 서버와 클라이언트를 함께 다시 빌드한다 (양쪽이 같은 값을 써야 예측이 맞는다).

## 자동 검증

Chrome이 설치된 환경에서 (경로는 `tests/lib.mjs`):

```bash
npm run build && npm run test:server   # 라운드 시간을 줄인 검증용 서버
npm run test:e2e     # 브라우저 세션 2개(1v1)·4개(2v2): 로비, 팀 배정, 라운드, 재대결, 재접속, 기권
                     # 느린 기기에서 4인 시나리오가 시간 초과로 끊기면 서버를 round=30 으로 띄우고 `node tests/e2e.mjs 2`
npm run test:misc    # 실제 키·마우스 입력, 장비 9종 수치, 상대 화면 연출
npm run test:knife   # 칼 3종: 꺼내기 → 질주 → 살펴보기 → 도중 공격 → 총 교체, 튀는 프레임 검사
npm run test:map     # 맵 대칭, 스폰 간 시야 차단, 교전 위치 도달 시간
```
